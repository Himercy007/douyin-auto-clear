# 抖音自动清屏

一个很小的 Chrome / Edge 浏览器扩展，解决一个很具体的麻烦事：

> 手动点了清屏，切到下一个视频，评论区又冒出来了，还得再清一次。

装上之后，**每次切换视频都会自动帮你清屏**，不用再手动点。

---

## 安装

1. 打开浏览器，地址栏输入 `chrome://extensions`（Edge 用 `edge://extensions`）
2. 打开右上角的 **开发者模式**
3. 点击 **加载已解压的扩展程序**
4. 选择本文件夹 `douyin-auto-clear`
5. 打开 [www.douyin.com](https://www.douyin.com) 任意视频，扩展自动生效

装好后浏览器右上角会出现一个红色播放图标，点它可以看到当前状态。

> 如果打开抖音时页面已经开着，刷新一次即可。

## 使用

默认就已经是「自动清屏」状态，不需要任何操作：

- 切视频（↑↓ 键、滚轮、自动连播都算）→ 评论区自动收起
- 想临时看评论 → 手动按 `J` 或 `X`，**这一条视频**不会被自动清屏，切到下一条时恢复

点扩展图标可以：

| 项目 | 说明 |
| --- | --- |
| 顶部开关 | 临时关闭/开启自动清屏 |
| 切换后延迟 | 默认 400ms。如果抖音加载慢导致偶尔没生效，可以调到 800ms 左右 |
| 调试日志 | 打开后按 F12 能在控制台看到判定过程，排查问题用 |
| 立即清屏一次 | 手动触发一次，方便验证 |

## 工作原理

抖音的「清屏」不是一个全局设置，而是**每个播放器实例自己的一个开关**（就是底部控制栏里那个"清屏"）。切换视频时抖音会创建新的播放器，这个开关默认是关的 —— 所以每条视频都得重新点一次。

扩展做了这几件事：

1. **精确定位当前播放器**：页面里同时挂着多个播放器（上一条、当前这条、预加载的下一条），靠 URL 里的视频 ID 匹配到容器的 `video_<id>` 类名，只认这种真正的视频容器，不按位置去猜。
2. **读状态**：开关带 `xg-switch-checked` 类就是已清屏，没有就是没清。（它的 `aria-checked` 属性永远是 `true`，不能用来判断）
3. **捕获切换**：轮询 + 监听 URL 和视频事件，上下滑动、↑↓ 键、自动连播都能捕获。
4. **持续守护**：清屏成功后不会就此撒手，还会一直盯着 —— 万一抖音把状态重置了（比如从直播预览滑回来），下一轮会自动补上。你自己手动关掉的会被识别出来，不会跟你抢。

每次点击后都会**回读状态做校验**，确认真的清屏了才算成功；失败会在同一条视频内重试，最多 15 轮，不会无限点击。

## 关于刷到直播预览

推荐流里滑动时偶尔会刷到「直播预览」——它用的是另一套播放器（`liveCardPlayer`），**根本没有清屏开关**。

这里有个坑：如果插件找不到当前开关就退而求其次"按位置猜"，会摸到上一条视频残留在 DOM 里的旧开关（那个是已清屏状态），于是误判成"当前已经清屏了"，导致后面所有视频都不再自动清屏。

所以现在的策略是：**认不准就什么都不做**。直播预览期间安静待着，滑到下一条视频、识别出真正的视频容器后，立刻恢复自动清屏。


## 失效了怎么办

抖音前端改版可能让选择器失效。如果发现不自动清屏了：

1. 点扩展图标 → 打开 **调试日志**
2. 打开抖音视频页，按 F12 看控制台里 `[自动清屏]` 开头的输出，能看到卡在哪一步（是没找到播放器，还是找到但点亮后状态没变）
3. 把日志贴出来，就能很快修好

## 文件说明

```
douyin-auto-clear/
├── manifest.json     扩展配置（MV3）
├── content.js        核心逻辑：定位播放器 / 读清屏状态 / 触发清屏
├── popup.html        图标弹窗界面
├── popup.css
├── popup.js
├── icons/            图标（16/32/48/128）
└── _dev/             开发调试脚本（不参与运行，无需安装）
```

扩展只用到了 `storage` 权限用于保存开关设置，不联网、不读取任何账号信息、不修改视频数据。
